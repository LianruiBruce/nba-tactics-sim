# 前瞻预测、对账和训练路线

目标：2026-27 赛季剩下的比赛，每次都在开赛前公开冻结预测（比赛分差、胜率、每队最可能的五人组净效率），赛后自动对账，和公开模型同台比较。规则在第一次预测前定死（本文件 + [data/forecast_config.json](../data/forecast_config.json)），之后只能升版本号、写明原因，不能回头改旧预测。

## 1. 每批预测包含什么

`scripts/forecast.py freeze` 在冻结时刻只用此前已经结束的比赛，输出到 `forecasts` 分支的 `<赛季>/<UTC 时间>/`：

| 文件 | 内容 |
| --- | --- |
| `games.csv` | 每场：预计回合数、主队分差和主队胜率。来源 `real`（我们的球员模型）、`rapm`、`team`，以及抓到时的 `market`（博彩盘口）和 `bpi`（ESPN BPI） |
| `lineups.csv` | 每场每队最可能的 5 套五人组、预计出场占比、对这个对手的预期净效率（每 100 回合） |
| `models/` | 这批用到的模型文件，任何人都能用它重算阵容对账 |
| `manifest.json` | 冻结时间、数据截止日期、代码 commit、全部参数、伤病名单剔除了谁，以及每个文件的 sha256 |

怎么从球员模型得到一场比赛的预测：

1. **预计轮换**：每队最近 10 场的五人组按回合数加权（越近权重越高，半衰期 4 场），去掉含有"最近 2 场都没上场"或伤病名单 Out 球员的组合，保留覆盖 90% 的前 30 套。
2. **逐对推演**：两队各套五人组两两配对，每个模型预测双方每回合得分（按回合开始方式加权：防守篮板后、对方投进后、失误后等）。
3. **汇总**：分差 = 预计回合数 × 加权后的每回合得分差；胜率 = Φ(分差 / σ)，σ 是每个模型在 2025-26 逐周回测里的分差误差，赛前固定。

`real`、`rapm`、`team` 用完全相同的数据和预计轮换，只差球员模型本身，所以它们之间的差距就是模型的差距。

## 2. 对手

| 来源 | 是什么 | 怎么拿到 |
| --- | --- | --- |
| RAPM | 业界最常用的球员正负值，十人在场的岭回归 | 我们自己按标准做法拟合，同数据同轮换 |
| 球队评分 | 只看攻防两队的岭回归（类似 SRS） | 同上 |
| 博彩盘口 | 让分和独赢赔率（去掉抽水后换成胜率），包含伤病、休息等全部公开信息，是最难赢的基准 | `scripts/fetch_lines.py` 从 ESPN 抓，和我们的预测同一时刻冻结 |
| ESPN BPI | ESPN 的比赛预测胜率 | 同上 |

FiveThirtyEight 已经停更，DARKO 等模型没有公开接口，所以没放进来；想加别的公开模型，只要在冻结前把它的预测写进 `games.csv` 的 `margin_<名字>` / `wp_<名字>` 列，记分牌会自动纳入。

## 3. 计分规则（预注册）

- **一场比赛只算一次**：取开赛前最后冻结的那一批。冻结时间取"文件里记录的时间"和"git 提交时间"中较晚的那个；开赛后才提交的不算。GitHub 上的推送记录是公开时间戳。
- **比赛指标**：分差 MAE / RMSE、胜负命中率、Brier 分数、对数损失。
- **"赢过"的标准**：逐场配对比较"我们的误差 − 对手的误差"，对比赛做自助抽样，95% 区间整体小于 0 才算赢；区间跨过 0 就是"未分胜负"。主指标是分差平方误差和 Brier，分别对每个对手报告。
- **阵容指标**，两种口径：
  - *赛前*：`lineups.csv` 里每批每个五人组的预测净效率，和它在这批比赛里实际打出的净效率比，按回合数加权。样本很小，看赛季累计。
  - *给定实际上场人员*：用每批冻结的模型去预测实际打出的每个回合，赛季累计后比较五人组净效率（至少 200 回合）。和 `backtest.py` 的阵容指标同一口径，模型是赛前冻结的，所以仍然是真正的样本外。
- 记分牌：`forecasts` 分支的 `<赛季>/scoreboard.md`，每次运行都从全部批次重算。

## 4. 在你的电脑上运行

数据来自 nba.com 和 ESPN，云端访问不了，所以每周（或每天）在 Windows 电脑上运行一次。第一次：

```powershell
cd C:\Users\gengl\Documents\nba-tactics-sim
git pull
pip install -e ".[dev,data]" scikit-learn scipy
python scripts\weekly.py
```

`weekly.py` 依次做：刷新 2026-27 数据和赛程 → 生成回合数据 → 抓盘口、BPI 和伤病名单 → 给已完赛比赛记分 → 冻结未来 7 天的预测（模型每 7 天重训一次，约 5 分钟）→ 提交并推送到 `forecasts` 分支（第一次会自动创建，工作目录在 `..\nba-forecasts`）。

常用参数：

```powershell
python scripts\weekly.py --days 2                          # 只预测未来两天（每天跑时用）
python scripts\weekly.py --out "Embiid, Haliburton"        # 手动标记缺阵球员（伤病名单之外的）
python scripts\weekly.py --no-push                         # 先在本地看结果，不推送
```

推荐每天跑一次：盘口和伤病名单越接近开赛越准，我们的预测也要在同一时刻冻结才公平。用 Windows 任务计划程序自动运行（北京时间每天 20:00，即美东早上 8 点，在当天比赛之前）：

```powershell
schtasks /Create /SC DAILY /ST 20:00 /TN nba-forecast /TR "cmd /c cd /d C:\Users\gengl\Documents\nba-tactics-sim && python scripts\weekly.py --days 2 >> forecast.log 2>&1"
```

单独的步骤：

```powershell
python scripts\fetch_nba.py --seasons 2026-27 --refresh    # 新比赛 + 赛季统计 + 赛程
python scripts\build_dataset.py --seasons 2026-27
python scripts\fetch_lines.py --days 7
python scripts\forecast.py score
python scripts\forecast.py freeze --days 7
```

## 7. 训练路线

整条链路是固定的，每一环都有对应脚本，改进只能在"验证"这一环证明有效后才能上线：

```
数据刷新            fetch_nba.py --refresh, build_dataset.py
   ↓
特征 / 模型         nbasim/realmodel.py（失误、造犯规、投篮选择、命中、前场篮板，十人在场的逻辑回归）
   ↓                + 残差岭回归；基线 nbasim/baselines.py
验证（离线）         backtest.py（给定上场人员）+ walkforward.py（完全赛前，含轮换预测）
   ↓
冻结 / 公开          forecast.py freeze → forecasts 分支（git 时间戳 + sha256）
   ↓
对账                forecast.py score → scoreboard.md
   ↓
改进 → 回到验证
```

**改进的规则**（防止事后挑结果）：

1. 新想法先在 2025-26 的逐周前推上跑（最好再加 2024-25），用配对自助区间证明比当前版本好，Brier 和分差误差都不能变差。
2. 通过后把参数写进 `data/forecast_config.json`，`version` 加 1，在本节末尾记一行：日期、改了什么、回测提升多少。
3. 新版本只影响之后冻结的预测；旧批次带着自己的 manifest 和模型文件，永远按原样计分。

**下一步按预期收益排序**：

| 顺序 | 改进 | 为什么 |
| --- | --- | --- |
| 1 | 伤病名单接 NBA 官方赛前报告（Questionable / Doubtful 按概率处理），伤愈复出球员重新放回轮换 | 现在只用 ESPN 的 Out 和"最近两场没上"，复出球员会被漏掉；盘口最大的信息优势就在这里 |
| 2 | 上场时间模型：按球员预测分钟数，再组合出五人组，代替"照搬最近 10 场的五人组" | 新组合、交易后的球队、首发调整都能覆盖；赛季初样本少时尤其重要 |
| 3 | 赛季内权重：本赛季的回合权重随场次增加，上赛季作为先验 | 现在每个赛季权重固定（2025-26 和 2026-27 都是 1.0） |
| 4 | 赛程因素：背靠背、休息天数、客场连战、海拔 | 公开研究里每项约 1–2 分，盘口都有考虑 |
| 5 | 回合数模型：按两队五人组预测节奏，代替两队近期平均 | 影响分差的放大倍数 |
| 6 | σ 按比赛调整（强弱悬殊、回合数）；定期用已对账的比赛重估 | 改善胜率校准（Brier / 对数损失） |
| 7 | 把模拟引擎接进来：用 `simulate.py --real` 跑战术层面的推演，对比模型推演 | 引擎和模型一致后，才能做第 8 步 |
| 8 | 强化学习（MAPPO，PettingZoo 环境，RTX 4080）在校准过的引擎里找新战术，再用真实数据检验 | 长期目标；只有引擎能复现真实效率时，学出来的东西才可信 |

1–6 每一项都可以独立做、独立验证、独立上线。

**版本记录**

- v1（2026-10-27）：初版。参数用 2025-10-01 之前的数据调好（真实模型 C=0.006、残差 α=9000，RAPM α=2000，球队 α=1000）；σ 来自 2025-26 逐周前推。
